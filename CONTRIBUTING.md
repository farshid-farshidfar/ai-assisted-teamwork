# Improve this guide

Corrections and beginner feedback are welcome. You can contribute using just your browser and a GitHub account; you do not need to install VS Code or learn Git first.

## Suggest an improvement

An **issue** is a message about a problem or suggestion.

1. Sign in to GitHub and [open a new issue](https://github.com/farshid-farshidfar/ai-assisted-teamwork/issues/new).
2. Add a short title and explain which page needs improving. For a setup problem, include your operating system, what you expected, and what happened.
3. Click **Submit new issue**.

For example: “I use Windows. In step 3, I could not find the button mentioned.”

More detail: [GitHub's instructions for creating an issue](https://docs.github.com/en/issues/tracking-your-work-with-issues/using-issues/creating-an-issue).

## Propose a text edit

1. Open the file you want to improve in [this repository](https://github.com/farshid-farshidfar/ai-assisted-teamwork).
2. Click the pencil icon. If GitHub asks, choose **Fork this repository**. A fork is your own copy where you can propose edits.
3. Edit the text, check **Preview**, then click **Commit changes…** and **Propose changes** as prompted. Add a short explanation of your correction.
4. Click **Create pull request** to send your proposal to this repository.

A **pull request** asks the maintainer to review your edits. The maintainer can discuss or accept them; your proposal does not automatically change the guide.

More detail: [GitHub's instructions for editing another person's files](https://docs.github.com/en/repositories/working-with-files/managing-files/editing-files#editing-files-in-another-users-repository).

## Keep contributions useful

Remove confidential information from examples and screenshots.

For changes to installation instructions, link the current official documentation. For a new workflow, explain who it helps and how they can check that it worked.

Keep the main starting route short. Define technical terms where needed, make one next action clear, and avoid promises about universal suitability, cost, or AI accuracy.

Before submitting, check relative links, code fences, and the example files. If you tested an installation, state the operating system and tool version. Do not describe a link check as an end-to-end setup test.
